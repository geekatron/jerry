## L0: Executive Summary

**Total pip residue artifacts: 17 actionable items** across 7 categories, plus approximately 40+ references in archived documentation (`docs/archive/`) that are inert but create confusion.

**Risk Level: MEDIUM.** Three artifacts actively cause harm today:

1. **`requirements-test.txt`** -- Dependabot PR #251 proved this file triggers false dependency update proposals. The `uv` ecosystem in Dependabot does NOT scan `requirements*.txt` files (confirmed via [dependabot-core issue #13912](https://github.com/dependabot/dependabot-core/issues/13912)), but other Dependabot ecosystem detection heuristics may still pick them up as `pip` ecosystem files. The file contains stale pinned versions (gherkin-official 29.0.0) that conflict with current `uv.lock` state.

2. **`release.yml` lines 157-160** -- Actively bundles all three requirements files into every release archive with the comment "Requirements files for pip fallback." This means every Jerry release ships dead files that mislead users into thinking pip installation is supported.

3. **`dependabot.yml` group name `pip-minor-patch`** (line 194) -- The group is named for the old pip ecosystem but now operates under the `uv` ecosystem. While functionally harmless, the naming creates confusion for maintainers reviewing Dependabot PRs.

**What this means for the project:** These dead files are not just clutter -- they are actively generating noise (Dependabot PRs), shipping misleading artifacts (release archives), and creating H-05 governance confusion. Removing them is a low-effort, high-signal cleanup.

## Methodology

- **Search scope:** Entire repository (`/Users/adam.nowak/workspace/GitHub/geekatron/jerry-wt/feat/PROJ-024-tactical-work-3/`)
- **Tools:** Glob (file discovery), Grep (content search), Read (file inspection), WebSearch/WebFetch (Dependabot behavior verification)
- **Patterns searched:** `pip install`, `pip3 install`, `python -m pip`, `pip freeze`, `pip compile`, `pip-audit`, `requirements*.txt`, `requirements-`, `setup-python`, `pip fallback`, `pip.*ecosystem`
- **Exclusion rationale:** `pip-audit` tool name references are NOT counted as pip residue because pip-audit is a legitimate PyPI package name for a security auditing tool that happens to contain "pip" in its name. It is correctly invoked via `uv run pip-audit`.
- **Source verification:** Dependabot uv ecosystem behavior confirmed via [dependabot-core issue #13912](https://github.com/dependabot/dependabot-core/issues/13912) -- the uv updater does NOT update requirements.txt files.
