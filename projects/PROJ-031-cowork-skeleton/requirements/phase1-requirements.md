## L0: Executive Summary

Jerry cannot be installed as a Claude CoWork plugin today because the repository contains approximately 6,344 tracked files, exceeding CoWork's plugin-load limit of roughly 5,000 files. The `projects/` folder (4,600 files, 72% of the total) is internal work history that CoWork users never need. The `tests/` directory, `skills/.graveyard/` (archived skills whose duplicate name blocked the marketplace), and `.github/` (framework CI that triggered a loop-safety violation) are similarly excluded from the distribution surface. **Phase-3 live-install validation (2026-07-02):** the validated strip-set (`projects/ tests/ skills/.graveyard/ .github/`) produces **1,399 tracked files**, empirically confirmed by a clean install on Claude Web — the dedicated-repo distribution model is PROVEN for the install path. **Install-validated ≠ G-update (P-022):** update-propagation to already-installed users remains OPEN (REQ-054). Per the Phase-2 architecture of record (ADR-PROJ031-003), the skeleton is now distributed as the default branch of a dedicated public repository (`geekatron/jerry-claude-plugin`) rather than as an in-source branch.

These requirements define what the solution must achieve across five workstreams: (1) a skeleton branch generated by stripping `projects/`, `tests/`, `skills/.graveyard/`, and `.github/` from the tagged release commit (validated strip-set, ADR-PROJ031-001 c-003 Phase-3 amendment) and injecting a minimal stub so the Jerry command-line interface still boots on a fresh install, then force-pushed to the **dedicated repo** `geekatron/jerry-claude-plugin`; (2) a CI workflow that regenerates this branch automatically on every `v*` release tag with loop-safety and least-privilege security; (3) security controls on the CI pipeline including no secret leakage, minimum token scope, and supply-chain integrity; (4) Diataxis-quadrant documentation wired into the MkDocs site; and (5) C4 adversarial quality gates (all 10 strategies, composite score >= 0.95) at every phase boundary before any irreversible action is authorized.

**Claim-Status Convention (P-022):** All Phase-2 WS-3 controls in this document are *Designed — operational validation pending* the Phase-5 gate indicated in brackets (e.g., `[G-prevention pending]`). None is an achieved fact until its corresponding Phase-5 gate passes. The six go-live gates are non-deferrable and defined in the [Phase-5 Authorization Checklist](#phase-5-authorization-checklist). **STK-002 contingency (REQ-054 / OQ-048):** The statement that the CoWork distribution remains "automatically in sync" with `main` on every release is contingent on the UNVERIFIED assumption that CoWork propagates default-branch updates to already-installed users within a bounded window. Only install-time behavior has been confirmed. Update behavior for existing users is an unexamined black box; STK-002 is re-scoped as contingent on G-update being verified before go-live.
