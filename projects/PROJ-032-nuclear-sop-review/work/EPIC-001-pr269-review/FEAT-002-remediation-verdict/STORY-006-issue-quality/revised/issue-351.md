TITLE: nuclear-sop — how does the user-approval pause actually reach a human? (runtime model, PR #269; internal ref: PROJ-032/BUG-002)

Assignees: victorlau1, malcolm-x-evo

**What this is about:** the skill's user-approval pause ("USER-HOLD": stop work, ask a human before proceeding) calls an interactive prompt tool (`AskUserQuestion`) that none of its four agents (sop-brief, sop-executor, sop-verifier, sop-capture) is granted and no agent in this repository has. Deeper problem: the docs never pin down *how the skill actually runs* — as a background worker agent (which cannot currently pause mid-run to converse with a human under the skill's present design) or as the main-session persona (which would undercut the per-agent tool restrictions and independent-verifier isolation documented elsewhere). Every USER-HOLD-style approval gate — sop-executor's USER-HOLD plus sop-brief's seven pre-job STOP conditions — inherits this ambiguity. (The separate quality-gate hold point is tracked in issue #350 — a different root cause: agent-to-agent delegation, not a missing tool grant.) Related: the rule "run a self-check before every Write, Edit, or command-execution step" never terminates as written — recording the self-check is itself a file write.

**The design question to answer:** what is the pinned runtime execution model, how do USER-HOLD and the briefing agent's seven interactive gates actually reach a human under it, and what is the terminating scope of the self-check rule? Closure also requires: a timeout/unattended-mode policy for a stalled USER-HOLD; whether the check that today only warns when an autonomous C3+/C4 workflow has no hold points (SR-02) should hard-stop instead; and a token/context-budget model justifying the skill's step limits, brief size, and checkpoint mechanism. The list is partial — the register also covers under-specified sub-procedure splitting when a procedure exceeds its step ceiling. One candidate: if the agents stay background workers, USER-HOLD becomes a return-to-orchestrator step (orchestrator asks the human, then resumes); if they run as the main session, the tool-isolation guarantees above need re-justifying.
