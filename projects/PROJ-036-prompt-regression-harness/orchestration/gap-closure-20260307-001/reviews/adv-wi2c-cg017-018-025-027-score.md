## Detailed Dimension Analysis

### Completeness (0.88/1.00)

**Evidence:**

- **CG-017:** Fully implemented. `_MAX_OUTPUT_CHARS: int = 8000` constant at line 93 with a three-line explanatory comment. Truncation guard at lines 410-420 in `evaluate_batch()` fires before `LLMTestCase` construction, exactly as required. Warning log records both original and truncated lengths, enabling audit.

- **CG-018:** Fully implemented. `str(value).replace("\n", " ").replace("\r", " ")` at lines 485 and 494 covers both `\n` and `\r` as required. Applied symmetrically in both the GHA file-write path and the logger fallback path. The "CG-018B" agent ID format validation in `main()` at line 603 (`re.match(r"^[a-z][a-z0-9_-]*$", args.agent)`) is a bonus input guard.

- **CG-025:** Implemented as `_validate_output_path` (lines 396-421) using `path.resolve()` and `Path.cwd().resolve()`. The method is called in `_persist_report` for both JSON and Markdown paths before any `write_text()` call.

- **CG-027:** Fully implemented. `VERSION_KEY_PATTERN = re.compile(r"^[0-9a-f]{7,40}:[^\n\r\0]+$")` at line 71 in `store.py`. Applied in `_validate_version_key` at line 454. Structural colon-split check precedes the regex, maintaining the original validation as a first-pass guard.

**Gaps:**

1. **CG-025 string-prefix collision:** The containment check at line 416 uses:
   ```python
   if not str(resolved).startswith(str(cwd)):
   ```
   This is incorrect when a sibling directory shares a name prefix. For example, if CWD is `/tmp/project` and the resolved path is `/tmp/project-evil/../../etc/passwd`, the `resolve()` call will correctly return an absolute path, but if CWD is `/app` and resolved is `/application/secret`, `str(resolved).startswith("/app")` returns `True` — a false pass. The correct idiom in Python 3.9+ is `resolved.is_relative_to(cwd)`, or at minimum `str(resolved).startswith(str(cwd) + os.sep)` to ensure the separator terminates the prefix match. This is a functional correctness deficiency in the implemented guard.

2. **CG-018B cross-reference:** The `main()` agent-ID validation in `layer4_stats.py` (line 603) uses a comment label "CG-018B" but the original CG-018 requirement was defined as "Sanitize newlines in GHA output values." The relationship between newline sanitization and agent ID format validation is not explained; a casual reader cannot confirm CG-018B is in scope for CG-018.

**Improvement Path:** Fix CG-025 to use `resolved.is_relative_to(cwd)` (Python 3.9+) or add `+ os.sep` to the startswith check. Add a one-line comment to CG-018B clarifying how it relates to CG-018.

### Methodological Rigor (0.88/1.00)

**Evidence:**

- All four validations follow the "validate early, fail fast" pattern: CG-027 validation happens at the top of `store()` before any I/O; CG-025 validation happens before any `write_text()`; CG-017 truncation happens before `LLMTestCase` construction; CG-018 sanitization happens at the point of writing the output value.

- Error messages across all four CGs include the failed value, the constraint, and the CG reference number, enabling post-hoc debugging without source code access.

- The post-batch zero-array assertion in `evaluate_batch()` (lines 500-522) is a defense-in-depth mechanism that elevates the systemic failure signal beyond individual per-output logging.

- `_validate_version_key` uses a two-stage validation: structural check (colon presence, non-empty components) then regex check. This produces more informative errors than a single regex match would (a structural failure produces a clearer message than a regex mismatch against a key with no colon).

**Gaps:**

1. **CG-025 `startswith` methodology:** Using string prefix matching to test path containment is a known antipattern. The Python pathlib documentation for `Path.is_relative_to()` (3.9+) specifically exists to replace this pattern. The current code passes a less rigorous containment check than the methodology requires for a path traversal guard.

2. **No symlink re-check after resolve:** `path.resolve()` follows symlinks, so a symlink pointing outside CWD would resolve to an out-of-bounds path and be caught. However, a symlink to an in-bounds path that itself has a nested symlink chain is followed by `resolve()`, which is correct. No gap here; `resolve()` handles all symlink cases correctly.

**Improvement Path:** Replace `str(resolved).startswith(str(cwd))` with `resolved.is_relative_to(cwd)` (Python 3.9+, confirmed available per the `from __future__ import annotations` usage pattern which targets modern Python).
